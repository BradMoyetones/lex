# Lex Engine v1.0.0

> Esta versión introduce la capacidad de gestionar módulos dinámicos basados en contratos JSON, permitiendo una flexibilidad sin precedentes en la gestión de datos. Por el momento está en modo prueba, esta versión aun sigue en desarrollo.

Hola este es **Lex**, mi motor de software dinámico construido en **Rust**. La magia de Lex es que la API y la base de datos se adaptan automáticamente a los contratos definidos en archivos JSON (`lex.json`), sin necesidad de recompilar el código para cada nuevo módulo.

## 🚀 Cómo empezar

1. **Configurar el entorno:** Asegúrate de tener un archivo `.env` con la URL de tu base de datos Postgres:
```env
DATABASE_URL=postgres://usuario:password@localhost:5432/lex_db
```


2. **Ejecutar el motor:**
```bash
cargo run
```

## Endpoints Disponibles

He diseñado estos endpoints para gestionar cualquier módulo (como `inventory`) de forma dinámica:

### 1. Status del Motor

Para verificar que Lex está vivo y coleando.

* **GET** `http://localhost:3000/`

```bash
curl -X GET http://localhost:3000/
```

### 2. Listar Registros (Read)

Recupera todos los datos guardados en el namespace correspondiente.

* **GET** `http://localhost:3000/api/modules/inventory`

```bash
curl -X GET http://localhost:3000/api/modules/inventory
```

### 3. Crear Registro (Create)

Envía datos para que Lex los valide contra el contrato y los guarde en la DB. ¡Si la tabla no existe, Lex la crea por ti!

* **POST** `http://localhost:3000/api/modules/inventory`
* **Body (JSON):** `{"sku": "LEX-SRV-101", "stock": 50}`

```bash
curl -X POST http://localhost:3000/api/modules/inventory \
     -H "Content-Type: application/json" \
     -d '{"sku": "LEX-SRV-101", "stock": 50}'
```

### 4. Actualizar Registro (Update)

Modifica un registro existente usando su ID (UUID).

* **PUT** `http://localhost:3000/api/modules/inventory/{id}`
* **Body (JSON):** `{"stock": 150}`

```bash
curl -X PUT http://localhost:3000/api/modules/inventory/PONER-AQUI-TU-UUID \
     -H "Content-Type: application/json" \
     -d '{"stock": 150}'
```

### 5. Borrar Registro (Delete)

Elimina físicamente un registro de la tabla.

* **DELETE** `http://localhost:3000/api/modules/inventory/{id}`

```bash
curl -X DELETE http://localhost:3000/api/modules/inventory/PONER-AQUI-TU-UUID
```

### 6. Describir Módulo (Introspección)

Este es el "espejo". Devuelve el JSON del contrato para que el Front-end sepa cómo dibujarse.

* **GET** `http://localhost:3000/api/modules/inventory/describe`

```bash
curl -X GET http://localhost:3000/api/modules/inventory/describe
```

## Lo que Lex hace por debajo

* **Namespacing:** Organiza la base de datos mediante **Schemas** de Postgres (ej: `core.inventory`).
* **Validación Dinámica:** Valida tipos, Regex y rangos numéricos antes de tocar la DB.
* **Infraestructura Automática:** Si el módulo es nuevo, genera el DDL (`CREATE TABLE`) al vuelo.
